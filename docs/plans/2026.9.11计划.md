---

## 0. 一句话目标

**不是「仿 n8n UI」，而是做一个面向 AI Agent + 机器人比赛的 Workflow Studio，n8n 退到后台作为执行引擎。**

---

## 1. 定位与方向

参考图的核心**不是「卡片好看」**，而是三件事同时变了：

| 维度 | 变化 |
| --- | --- |
| UI | 无限画布 + 圆角卡片节点 + 曲线连线 + 深色主题 |
| 数据结构 | 从线性链路 → 多端口图（主执行 / 模型 / Memory / Tool / 条件分支） |
| 交互方式 | 拖拽连线 + 运行态实时高亮 + 节点级 Inspector |

所以这张图**不是「把 n8n 换个皮肤」那么简单**。但也不必因此重写执行引擎。

---

## 2. 架构结论：不重写 n8n 执行引擎

```text
我们自己的工作流 UI
        ↓
工作流定义 / Graph JSON
        ↓
适配层（Workflow Adapter）
        ↓
n8n
        ↓
AI / 数据库 / API / 机器人 / 外部服务
```

**前端长得像参考图，底层继续让 n8n 干活。** 这是目前最划算的方案。

---

## 3. 真正要改成的形态

节点不再只是 `A → B → C → D`，而是允许存在：

```text
Trigger
   ↓
AI Agent
├── Chat Model
├── Memory
└── Tools
     ├── Tool A
     ├── Tool B
     └── Tool C
   ↓
Condition
 ┌─┴─┐
true false
 ↓    ↓
动作A  动作B
```

需要支持的连接类型：

```text
主执行连接（main）
模型连接（model）
Memory 连接（memory）
Tool 连接（tool）
条件分支（true / false，未来扩展多 branch）
子工作流（subworkflow）
```

这才是最大的结构变化。

### 第二阶段：定义统一的 Graph Schema（**整个项目最重要的一步**）

以后一个工作流不要直接绑死 n8n，而是我们自己定义：

```json
{
  "nodes": [],
  "edges": [],
  "version": 1
}
```

**AI Agent 节点：**

```text
AI Agent

inputs:
- main

resources:
- model
- memory
- tools

outputs:
- main
```

**Condition 节点：**

```text
Condition

input:
- main

outputs:
- true
- false
```

**Tool 节点（种类）：**

```text
HTTP Tool
Database Tool
Robot Tool
Search Tool
Jira Tool
Slack Tool
```

这样以后 UI 才能真正像参考图。

Schema 至少需要支持：

```text
Workflow
Node
Edge
Port
Main Input / Main Output
Model Port
Memory Port
Tool Port
Conditional Output
Node Configuration
Runtime State
Execution Result
```

### 第三阶段：工作流 UI

目标布局：

```text
┌──────────────────────────────────────────────┐
│ Workflow Name       ▶ Run     Save    Deploy │
├──────────┬───────────────────────────────────┤
│          │                                   │
│ Nodes    │            Canvas                 │
│          │                                   │
│ Trigger  │      ┌───────────────┐            │
│ Agent    │ ───→ │   AI Agent    │ ───→       │
│ Logic    │      └───────────────┘            │
│ Data     │        ◇    ◇    ◇                │
│ Tools    │        │    │    │                │
│          │      Model Memory Tools           │
│          │                                   │
├──────────┴───────────────────────────────────┤
│ Execution / Logs / Output                    │
└──────────────────────────────────────────────┘
```

技术选型（优先评估复用，不要盲目引入新依赖）：

```text
React + React Flow / XYFlow
```

因为它天生适合：

```text
拖拽节点 / 连线 / Handle 接口 / 缩放 / 移动 / 节点选中
MiniMap / 条件分支 / 自定义节点
```

---

### 第四阶段：AI Agent 节点（UI 的核心）

**不要把 Agent 做成普通矩形节点。**

```text
┌────────────────────────────┐
│ 🤖 AI Agent                │
│                            │
│ Tools Agent                │
└────────────────────────────┘
   ◇           ◇          ◇
 Model       Memory      Tool
```

连接示例（Tool 必须支持一对多）：

```text
             AI Agent
                │
       ┌────────┼────────┐
       ↓        ↓        ↓
   Database   Robot    HTTP API
```

```text
Claude          ── Model
Postgres Memory ── Memory
HTTP Tool       ── Tool
Robot Control   ── Tool
```

这样比赛项目才有「Agent 系统」的感觉，而不是普通后台管理页面。

---

### 第五阶段：运行效果（Runtime UI）

运行不能只是「点 Run 然后等结果」，要动态展示：

```text
Trigger
 🟢
  ↓
AI Agent
 🟡 Running...
  ↓
Condition
 ⚪ Waiting
```

完成后：

```text
Trigger        ✅ 82 ms
    ↓
AI Agent       ✅ 2.31 s
    ↓
Condition      ✅ 12 ms
       ↓ true
Robot Action   ✅ 315 ms
```

点节点可查看：

```text
INPUT
OUTPUT
LOG
ERROR
DURATION
REQUEST ID
```

状态机：

```text
idle / waiting / running / success / error
```

这块对比赛展示比「画漂亮节点」重要得多。

---

### 第六阶段：n8n 适配层

前端**不要**直接理解 n8n 的所有内部结构，做一个 Workflow Adapter：

```text
Our Graph JSON  →  Workflow Adapter  →  n8n Workflow JSON
n8n Workflow    →  Workflow Adapter  →  Our Graph
```

好处：以后可以换运行时而 UI 不用推倒重做：

```text
n8n  →  LangGraph  →  自研 Runtime
```

这就是要提前把架构做干净的原因。

## 5. 第一版范围（不要现在就追求「100% 像图里」）

**第一版只做这六样，真正跑通：**

```text
1. 节点拖拽
2. 连线
3. Agent Model / Memory / Tool 端口
4. Condition 分支
5. 保存 Workflow
6. 运行 Workflow
7. 节点运行状态
```

**跑通之后再做：**

```text
动画 / 阴影 / 渐变 / 发光 / 右键菜单 / 快捷键
MiniMap / 自动布局 / 节点搜索 / Command Palette
```

否则很容易花三天做出一个很酷的编辑器，**然后发现它只是能拖卡片，真正工作流根本跑不起来**。
