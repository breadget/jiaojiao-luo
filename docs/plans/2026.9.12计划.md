## 1. 原则：AI ≠ Shell（两周内不许破坏）

```text
AI
 ↓
结构化 Action（JSON）
 ↓
Control Server（权限 / 白名单 / 参数校验）
 ↓
真正执行 Shell / PowerShell / Python
 ↓
Windows
```

AI **永远不允许**输出：

```powershell
taskkill /f /im xxx.exe
```

AI **只允许**输出：

```json
{ "action": "stop_app", "params": { "app": "notepad" } }
```

然后由 Control Server 决定：

```text
这个 action 能不能执行？
这个程序允不允许关闭？
参数是否合法？
超时多少？
要不要人工确认？
```

最后才执行。**这一条决定了系统是「比赛 Demo」还是「像样的 Agent 系统」。**

第二原则：

> **有 Python API 就优先 API，没有 API 再 Shell。**

第三原则（Day 1 就要落地）：

> **新增一个动作 = 新增一份能力契约。** 每个 action 必须同时声明：参数模型、权限级别、超时、副作用说明。缺一项不允许注册。

## 5. 接口契约（今天定死，两周内不改）

### 5.1 `GET /health`

响应 `200`：

```json
{
  "status": "online",
  "version": "0.1.0",
  "platform": "Windows-10-10.0.22631-SP0",
  "python": "3.11.9",
  "started_at": "2026-09-12T19:22:31+08:00"
}
```

> 多返回这四项不费时间，但 Day 6 n8n 做存活检测、Day 13 Dashboard 显示 `ONLINE` 徽标时直接就用上了，不用回头改接口。

### 5.2 `POST /action`

请求：

```json
{
  "requestId": "req_893124",
  "action": "python_version",
  "params": {}
}
```

- `requestId` **可选**：不传 → 服务端生成 `req_` + 6 位随机串并回传；传了 → **原样透传，绝不覆盖**。
- `params` **可选**，默认 `{}`。
- **不接受任何其他字段**（`extra="forbid"`），防止有人偷偷塞 `command` 字段进来。

成功响应 `200`：

```json
{
  "requestId": "req_893124",
  "action": "python_version",
  "success": true,
  "data": { "output": "Python 3.11.9", "raw": "Python 3.11.9", "duration_ms": 42 },
  "message": "",
  "error": null,
  "duration_ms": 42,
  "timestamp": "2026-09-12T19:22:31+08:00"
}
```

失败响应 `200`（**注意：业务失败仍返回 200，只有协议层错误才用 4xx/5xx**）：

```json
{
  "requestId": "req_893125",
  "action": "rm_rf_everything",
  "success": false,
  "data": null,
  "message": "未知动作",
  "error": { "code": "UNKNOWN_ACTION", "detail": "action 'rm_rf_everything' is not registered" },
  "duration_ms": 1,
  "timestamp": "2026-09-12T19:22:31+08:00"
}
```

**关于状态码的取舍（写进 README，避免以后争论）：**

| 情况 | HTTP 状态 | 说明 |
| --- | --- | --- |
| 执行成功 | 200 | `success: true` |
| 未知动作 / 参数非法 / 权限不足 / 超时 / 执行失败 | **200** | `success: false` + `error.code` |
| 请求体不是合法 JSON / 缺 `action` 字段 | 422 | FastAPI 自动校验 |
| 服务器内部未捕获异常 | 500 | 兜底，且必须返回标准 JSON 体 |

理由：n8n 的 HTTP Request 节点对 4xx/5xx 默认会走 error 分支，而"AI 说了一个不存在的动作"属于**正常的业务流程**，不该被 n8n 当成工作流故障。把业务失败统一放 200，用 `error.code` 区分，Error Workflow 只会被真正的系统故障触发。

## 6. 统一错误码（今天定死，两周内不改）

| code | 含义 | 触发场景 | HTTP |
| --- | --- | --- | --- |
| `UNKNOWN_ACTION` | 未知动作 | action 不在注册表 | 200 |
| `INVALID_PARAMS` | 参数非法 | Pydantic 校验失败 / 类型不对 / 多余字段 | 200 |
| `PERMISSION_DENIED` | 权限不足 | 当前级别不允许自动执行 | 200 |
| `FORBIDDEN_ACTION` | 禁止的动作 | 命中保留名 / Level 3 动作 | 200 |
| `TIMEOUT` | 执行超时 | 超过该 action 的 timeout | 200 |
| `EXEC_FAILED` | 执行失败 | 子进程返回码非 0 | 200 |
| `NOT_FOUND` | 目标不存在 | 程序 / 脚本 / 文件找不到 | 200 |
| `INTERNAL_ERROR` | 内部错误 | 未捕获异常兜底 | 500 |

**保留动作名（今天就要拦住，永远不允许注册）：**

```text
run_command   exec   shell   cmd   powershell   bash
run_shell     system   raw_exec   eval   python_exec
delete_file   format_disk   regedit   set_acl   stop_service
```

拦截逻辑放在注册期（注册时就报错），而不是运行期。**让危险动作根本注册不进来**，比运行期判断更可靠。

## 7. 权限分级（今天只用 Level 0，但分级结构今天就建好）

| Level | 名称 | 内容 | 策略 |
| --- | --- | --- | --- |
| 0 | READ_ONLY | 查看 CPU / 内存 / 磁盘 / 进程 / 日志 / 版本 | 允许 AI 自动执行 |
| 1 | LOW_RISK | 打开程序 / 运行已批准脚本 | 允许自动执行 |
| 2 | HIGH_RISK | 关闭程序 / 停止进程 / 修改文件 | **需要额外确认** |
| 3 | FORBIDDEN | 格式化磁盘 / 删系统文件 / 改安全设置 / 任意 PowerShell / 任意 cmd | **绝对禁止** |

今天的落地方式：

```python
class ActionLevel(IntEnum):
    READ_ONLY = 0
    LOW_RISK = 1
    HIGH_RISK = 2
    FORBIDDEN = 3
```

- `registry.register()` 时，如果 `level == FORBIDDEN` → **直接抛异常，注册失败**（Level 3 永远进不了系统）。
- `security.authorize()` 今天只判断 `level <= MAX_AUTO_LEVEL`（今天设 `MAX_AUTO_LEVEL = 1`）。
- 服务启动时做一次自检：遍历注册表，若发现任何保留动作名 → **拒绝启动**。

这套结构以后原样复用到机器人：

```text
读取传感器 → 自动
移动机器人 → 自动
高速运动   → 确认
危险动作   → 禁止
```

## 8. 每个文件写什么（Day 1 逐文件说明）

### 8.1 `schemas/action.py` —— 契约层

需要定义四个模型：

```text
ActionRequest
  requestId : str | None   （正则 ^req_[A-Za-z0-9]{1,32}$，不合法则视为未提供）
  action    : str          （必填，长度 1..64，只允许 [a-z0-9_.]）
  params    : dict         （默认 {}）
  model_config = ConfigDict(extra="forbid")

ActionError
  code   : str
  detail : str | None

ActionResponse
  requestId   : str
  action      : str
  success     : bool
  data        : dict | None
  message     : str
  error       : ActionError | None
  duration_ms : int
  timestamp   : str        （ISO8601 带时区）

ActionDef          # 能力契约，由 registry 使用
  name         : str
  level        : ActionLevel
  description  : str
  params_model : type[BaseModel]
  timeout_s    : float    （默认 5.0，上限 60.0）
  side_effects : str      （"none" / "launches_process" / "terminates_process" / "writes_file"）
  handler      : Callable
```

**要点：**

- `action` 字段只允许小写字母、数字、下划线、点 —— 从格式上就堵死 `"action": "powershell -c ..."` 这种输入。
- `params` 保持 `dict`，**由每个 action 自己的 `params_model` 二次校验**。不要试图在这里做统一校验。
- 所有时间字段用带时区的 ISO8601（`datetime.now(timezone.utc).astimezone()`），否则 Day 5 日志时间会和 n8n 的时间对不上。

### 8.3 `actions/registry.py` —— 唯一可信白名单

```python
_REGISTRY: dict[str, ActionDef] = {}

def register(defn: ActionDef):
    name = defn.name
    if name in _REGISTRY:
        raise ValueError(f"duplicate action: {name}")
    if defn.level == ActionLevel.FORBIDDEN:
        raise ValueError(f"forbidden action cannot be registered: {name}")
    if is_reserved(name):
        raise ValueError(f"reserved action name: {name}")
    _REGISTRY[name] = defn

def get(action_name: str) -> ActionDef | None: ...
def all_actions() -> list[ActionDef]: ...
def registered_names() -> list[str]: ...
```

**要点：**

- 注册表是**进程内的、写死的**。任何"从配置 / 数据库 / 请求里动态注册 action"的做法，今天就要明确否决。
- 不提供 `unregister()`。白名单只能通过改代码 + 重启来变更，**变更必须留下 git 记录**。
- 装饰器风格（`@action(...)`）比集中列表更好看，但集中列表更容易一眼审出"今天系统能做哪些事"。今天用**显式列表 + 装饰器二选一都行**，但要在 README 里贴出完整白名单表。

### 8.4 `core/security.py` —— 校验与授权

三个职责，按顺序执行：

```text
1. validate(action_name, raw_params) -> (ActionDef, BaseModel)
   - action 存在？       否 → UNKNOWN_ACTION
   - 名字合法（格式）？   否 → INVALID_PARAMS
   - params 过 params_model ？ 否 → INVALID_PARAMS（把 Pydantic 错误压成一行 detail）

2. authorize(defn, context) -> None
   - defn.level == FORBIDDEN → FORBIDDEN_ACTION
   - defn.level > MAX_AUTO_LEVEL 且未带确认 → PERMISSION_DENIED
   - 今天：所有已注册动作都是 Level 0，所以永远通过；但分支必须写出来

3. 参数二次防御
   - 遍历 params 的所有字符串值：
       含 "\n" / "\r" / ";" / "|" / "&" / "`" / "$(" / ">" / "<" → INVALID_PARAMS
   - 路径类参数必须拼在允许的基目录下（realpath 后 startswith 校验）
   - 今天没有路径参数，但函数先写好并留 TODO，Day 3 / Day 4 直接用
```

**要点：**

- 参数二次防御**不是**为了替代参数数组调用，而是为了多层防御：即使某人以后偷懒写了 `shell=True`，这些字符也进不去。
- 拒绝后的 `detail` 要写清楚**哪个字段、什么原因**，否则 Day 8 AI 拿到错误也不知道怎么改参数重试。

### 8.5 `core/executor.py` —— 统一执行

```text
run_action(request_id, action_name, params) -> ActionResponse
  ├─ t0 = perf_counter()
  ├─ security.validate()        # 抛 ControlError
  ├─ security.authorize()
  ├─ defn.handler(validated_params)                  # 进程内调用（Day 2 起多是这种）
  │     或 subprocess 参数数组调用（Day 1 用一次，为了验证超时与截断）
  ├─ 结果归一化：str / dict / list → data
  ├─ 计时 duration_ms = (perf_counter() - t0) * 1000
  ├─ logger.record(...)
  └─ 返回 ActionResponse
```

**必须处理的六件事：**

1. **超时**：`subprocess.run(..., timeout=defn.timeout_s)`；`TimeoutExpired` → `ActionTimeout`。
2. **输出截断**：stdout / stderr 各保留前 8000 字符，超长时追加 `"\n...[truncated N chars]"`。
3. **编码**：Windows 强制 `encoding="utf-8", errors="replace"`。若 `stdout` 为 `None`，替换为空串。
4. **禁止 shell**：一律 `[exe, *args]` 列表形式，**全项目禁止出现 `shell=True`**（Day 1 完成后用全局搜索确认一次）。
5. **异常兜底**：`ControlError` 原样抛出；其他所有异常 → `InternalError`（记录完整 traceback 到日志，但**不返回给调用方**，防止泄露本机路径结构）。
6. **超时后的进程清理**：`subprocess` 超时后进程可能残留。Windows 下用 `CREATE_NEW_PROCESS_GROUP` 起进程，超时后 `taskkill /F /T /PID <pid>` 兜底。Day 1 用一个 `sleep 10` 的场景验证一次。

**不要在今天做的东西：** 并发执行、任务队列、重试机制、取消机制（Day 11 / Day 12 做）。

### 8.7 `actions/system.py` —— 今天唯一的动作

```text

```

**要点：**

- **优先 Python API，不解析 shell 输出**：`platform.python_version()` 直接可用，`sys.executable` 给出解释器路径。
- 返回：

```json
{
  "output": "Python 3.11.9",
  "version": "3.11.9",
  "implementation": "CPython",
  "executable": "C:\\...\\python.exe"
}
```

- `output` 字段是为了兼容你原计划的返回格式（`{"success": true, "output": "Python 3.x.x"}`），后续所有 action 都保留 `output` 作为"人类可读摘要"，另外字段放结构化数据。
- **不需要子进程**。但今天要额外写一个 `subprocess` 场景用于验证超时 / 截断（可以放在测试里，不要放进白名单）。

### 8.8 `app.py` —— 入口

```text
1. 创建 FastAPI(title="Computer Control Server", version="0.1.0")
2. lifespan 启动钩子：
     ├─ 导入 actions（触发注册）
     ├─ 启动自检：注册表非空 / 无保留动作名 / 无 Level 3 → 失败则拒绝启动
     ├─ logger.cleanup_old_logs(30)
     └─ 打印启动横幅：版本、Python、平台、已注册动作表、监听地址
3. 注册路由：GET /health、POST /action、GET /capabilities
4. 注册全局异常处理：
     ├─ RequestValidationError → 422 标准体
     ├─ ControlError          → 标准体（HTTP 由 errors.HTTP_STATUS 决定）
     └─ Exception             → 500 INTERNAL_ERROR（标准体，不泄露 traceback）
5. 绑定 127.0.0.1:8765
```

**端口选 8765**（避开 8000 / 8080 / 3000 / 5678，n8n 默认 5678）。

**绑定地址的取舍（今天先这样，Day 6 再改）：**

- 今天：`127.0.0.1` —— 只有本机能访问。**这是最安全的默认值**，Day 1–Day 5 全用本机测试足够了。
- Day 6 n8n 如果跑在 ECS 上再改成 `0.0.0.0`，**且必须同时加 API Key 校验**（`X-API-Key` 头）。**永远不要在没有鉴权的情况下把 Control Server 暴露到公网** —— 那等于把电脑的进程控制权挂到互联网上。

**启动横幅要打印已注册动作表**，这样每次启动你都能一眼看到"这台电脑现在允许被做哪些事"。这是一个很便宜、但答辩时很好用的展示点。

## 12. 避坑清单（Windows 特有，今天就会撞上）

| # | 坑 | 症状 | 处理 |
| --- | --- | --- | --- |
| 1 | PowerShell 里 `curl` 是 `Invoke-WebRequest` 别名 | 参数报错 / 中文乱码 | **必须写 `curl.exe`** |
| 2 | JSON 引号转义 | `-d "{...}"` 在 PowerShell 里被吞引号 | 用上面的 `\"` 写法，或改用 `--data-binary "@body.json"` |
| 3 | 中文输出乱码 | stdout 变乱码 | `encoding="utf-8", errors="replace"`；控制台先 `chcp 65001` |
| 4 | `python` 指向 Microsoft Store 占位程序 | 执行 python 弹出商店 | 用 `py -3.11` 或绝对路径 `sys.executable` |
| 5 | 端口 8765 被占 | 启动报 `WinError 10048` | `netstat -ano \| findstr 8765` 然后换端口或杀进程 |
| 6 | 子进程超时后残留 | `sleep` 进程还在跑 | `CREATE_NEW_PROCESS_GROUP` + `taskkill /F /T /PID` 兜底 |
| 7 | 相对路径依赖 cwd | 从别的目录启动找不到 `logs/` | 所有路径基于 `Path(__file__).resolve().parent` 绝对化 |
| 8 | 日志目录不存在 | 首次写日志报错 | 启动时 `mkdir(parents=True, exist_ok=True)` |
| 9 | 服务热重载叠加旧进程 | 端口占用 / 改了代码没生效 | Day 1 开发期用 `--reload`，收尾用不带 reload 的正式启动再验一次 |
| 10 | 编码声明缺失 | 读写非 ASCII 报 `UnicodeDecodeError` | 所有 `open()` 显式指定 `encoding="utf-8"` |

> ```
>
> 2. `POST /action`，请求：
>
> ```json
> { "requestId": "req_893124", "action": "python_version", "params": {} }
> ```
>
> 响应：
>
> ```json
> {
>   "requestId": "req_893124",
>   "action": "python_version",
>   "success": true,
>   "data": { "output": "Python 3.11.9", "version": "3.11.9", "implementation": "CPython", "executable": "C:\\...\\python.exe" },

>   "error": null,
>   "duration_ms": 42,
>   "timestamp": "2026-09-12T19:22:31+08:00"
> }
> ```
>
> 失败时 `success: false`，`error` 为 `{"code": "...", "detail": "..."}`。
>
