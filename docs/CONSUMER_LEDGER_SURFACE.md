## 1. 范围

这次只替换使用端的视觉世界。身份门厅、创建端和机器人端继续使用现有设计：

- 身份门厅仍是冷灰纸面与深海军蓝说明场。
- 创建端仍是黑蓝节点编排台。
- 机器人端仍是纸白控制面围绕深色视频窗。

使用端不再以纸白记录页、横线和常驻执行联页组织首屏。它是一张对话优先的工作台：左侧是真实聊天记录，右侧是当前对话；标题生成、持久化和执行证据在后台完成，需要时才展开。

## 3. 首屏结构

| 区域 | 实现 | 承担什么 |
| --- | --- | --- |
| 会话侧栏 | `.ledger-index` | 280px 石墨侧栏；品牌、收起、新对话、工作流、真实聊天记录、设置与切换工作端 |
| 会话列表 | `.ledger-list-chat` | AI 自动标题、更新时间和当前项；标题单行截断，不撑宽侧栏 |
| 当前会话栏 | `.ledger-head` | 当前标题、装载的工作流、运行时状态、执行详情开关和设置 |
| 对话流 | `.chat-stream` | 最大 840px，空会话只有图标与“想从哪里开始？”，有消息后展示真实轮次 |
| 输入容器 | `.composer-card` | 最大 860px，水平居中；输入在上，加号在左下，发送在右下 |
| 执行详情 | `.ledger-page-run` | 默认收起；显式展开后显示路线、日志、结果与台账 |
| 设置 | `.ledger-sheet` | 原生模态；模型、API、本机权限事实与本地保存位置 |

侧栏可以收为 72px，只保留品牌和导航图标。默认收起的是执行详情，不是对话本身；主画面宽度优先交给当前会话。

## 4. 对话、标题与持久化

- 新建对话后可以直接输入，不先要求用户理解工作流状态。
- 第一轮成功回复后，服务端根据用户消息与 Agent 回复生成短标题；标题同时出现在侧栏与页眉。
- 模型不可用或标题生成失败时，回退为首条请求的短标题，不打断对话。
- 侧栏读取持久化的会话摘要和更新时间，不使用示例卡假装历史记录。
- Agent 回复使用透明底连续文字和头像；用户消息靠右，以石墨气泡区分说话者。
- 失败、附件、产物、Python 运行和 Shell 命令都挂在对应轮次上，保持因果关系。

## 5. 颜色与形状

这些值均直接来自 `.consumer-workspace .ledger-shell` 及其组件样式：

| 角色 | 值 | 用途 |
| --- | --- | --- |
| 炭黑画布 | `#111214` | 主背景与当前对话 |
| 石墨侧栏 | `#1a1b1e` | 会话导航 |
| 抬升灰 | `#26272b` | 悬停和次级动作 |
| 冷灰边界 | `#303136` | 1px 分隔与边界 |
| 主文字 | `#f1f2f4` | 标题、正文和关键导航 |
| 辅助文字 | `#a3a6ad` | 状态与次要说明 |
| 弱文字 | `#757981` | 时间与低优先信息 |
| 柔和行动蓝 | `#7891c7` | 发送按钮 |
| 行动蓝悬停 | `#8ca6df` | 发送按钮悬停 |

输入容器使用 16px 圆角；导航控件使用 9–11px；发送按钮为 38px 圆形。用户气泡是 `16px 16px 4px 16px`，Agent 回复无外框。颜色和形状均限定在 `.consumer-workspace`，不覆盖其他工作端。

## 6. 设置与执行证据

- 执行面板默认收起，收起状态存在浏览器本地；用户通过页眉按钮展开或再次收起。
- 设置使用原生 `<dialog>` + `showModal()`：Esc、遮罩点击、焦点锁和关闭后归位交给 top layer。
- 加号菜单使用 `fieldset` + `legend` 分成附件、工作流和工作模式；当前项以 `aria-pressed` 表达，Esc 或外部点击关闭后焦点回到加号。
- “本机全权限”必须显示当前用户、uid、主机、Shell、默认目录、非沙箱与非 root 事实。
- 模拟、真实模型、n8n、Python 和 Shell 必须如实标记；失败留在原轮次，产物与日志可追溯。

## 7. 响应式

- **桌面：** 280px 侧栏 + 弹性对话主区；收起侧栏为 72px；执行面板展开时占 320–380px。
- **820px 以下：** 侧栏移到顶部，最大高度 230px；主要导航并排；执行详情成为主区覆盖层。
- **520px 以下：** 侧栏最大高度 190px，会话列表最大高度 68px；加号菜单改为单列；消息宽度不超过可用区域的 88%。
- 所有关键操作保持可见焦点；移动端可重复操作保持至少 44px 触控高度。

## 8. Finish Review

结论为 **pass with minor notes**，没有需要阻止交付的 material UI 问题。检测器对 `DESIGN.md` 的提示来自旧的浅色 ledger 描述，本轮已同步修正；机器人日志区域的 side-tab 提示不属于使用端替换范围。

## 9. 明确不做

- 不把状态总览、工作流说明、步骤和执行日志同时放进使用端默认首屏。
- 不在空会话堆教程、欢迎长文、建议卡片或多个主按钮。
- 不给 Agent 回复套高对比卡片；用户气泡才承担方向区分。
- 不把使用端炭黑与柔蓝扩散到身份门厅、创建端或机器人端。
- 不把模拟写成真实运行，不用动画伪造执行证据。
